### Five things a player notices missing in the first ten minutes

1. **There is no picture of the world.** `godot/project.godot` has no
   `run/main_scene` and the map panel is deleted. Measured:
   `grep -c '^run/main_scene' godot/project.godot` → **0**, control
   `grep -c '^config/name'` → 1 (the name appears twice in that file, both
   times in a comment saying why it is unset). The client plays without it
   (`test:viewer-absent`), so this is a Gate 3 item and the Godot owner's —
   recorded here because it is the first thing a person sees, not because
   this side should build it.
2. **Every activity button is greyed out.** The nine intents above are the
   ones behind Fight, Travel, Heal, Town run, Train, Loot and Buffs. The
   client is honest about it — `isIntentImplemented` disables them
   (`src/store/bridgePolicy.ts`, six call sites) — but honest and useless are
   the same thing to a player. Lane **R**.
3. **The client can set your stance and can never tell you what it is.**
   `src/data/macros.ts:58-66` sends `stance defensive|guarded|offensive`.
   `grep -c '\bstance\b' lich-scripts/companion_bridge.lic` → **0** (control:
   `injuries` → 13). DragonRealms never sends `pbarStance` on the XML stream
   either, which `src/types/stream.ts` says in so many words. So nothing
   anywhere reads it back. Lane **W**.
4. **Experience can read empty and look like an answer.** The skill table
   depends on DRInfomon's post-login `exp all 0`
   (`lich-scripts/companion_bridge.lic:379-393`), and `LIVE-STATE.md:285`
   records it reading empty on the one live run. `skillsReady` exists
   precisely to tell "not asked yet" from "no skills" — but mindstate is the
   loudest single need in the whole doc corpus (`DOMAIN.md:21-57`,
   `:586`), and it is the one a player checks every 200 seconds.
5. **The room's creature list is half-built on purpose, and the channel tabs
   were empty on the one live run.** `src/types/stream.ts` explains that the
   bold half of `<component id='room objs'>` needs a `crtrStatus` pairing the
   parser does not implement, so creatures are deliberately left out
   (`WIRING-AUDIT.md:172`); the bridge supplies `roomCreatures` separately, so
   a fight is readable, but the two sources have never been reconciled.
   `LIVE-STATE.md:354` records the channel tabs staying empty live, and
   `:320` records Lich having no map database at all on that run.

The **largest** absent block is not in that list because a player does not
reach it in ten minutes: **money, shops, repair, banking, bounties and
crafting — the entire town half of the session loop** (`DOMAIN.md:305-321`).
The bridge has no field for any of it. Lanes **X** (money, shops, repair,
banking) and **Y** (tasks and bounties).

**Crafting deliberately gets no lane**, and that is a decision rather than an
oversight. `DOMAIN.md:342` records what the client has as, in one word,
"nothing" — and the same table records why building it would be the wrong
move: `base-recipes.yaml` is 10,305 lines on the player's own disk,
maintained by people who play, and `:348` says plainly that reading the user's
installed copy beats duplicating it. The five crafting disciplines are a
whole product on their own. What this survey recommends instead is **Lane Z**:
make the crafting *settings* editable in forms, so the recipes the community
maintains can be used by somebody who has not installed VS Code. If that lands
and crafting still feels absent, a lane can be written then, from evidence.

## 1. What is already good, and must not be rebuilt

Stated first and at length, because a gap survey read on its own reads as a
verdict on the whole build, and it is not one. Four of these are better than
what the community's own tooling offers.

**The outbound command lane.** `src-tauri/src/command_gate.rs` is one ordered
path for every command the app can emit — typed, macro, keybinding, UI
button, AI suggestion, exit word, and every Lich or Python script through
`script_api::dispatch`. It carries priority (`player > ui-action > keybind >
macro > ai-suggestion > script`, and a player-typed command is never dropped
and never waits behind automation), roundtime pacing read from the game's own
`<roundTime>` tag, a typeahead allowance so it does not hold what the game
would accept, and per-source coalescing of repeated movement. Pause and the
kill switch reach all of it. There is nothing to redo here; new capability
**submits to this lane** and inherits it.

This also closes a note that was in Claude's memory as an open design item —
"no priority/rate lane spans UI/macros/scripts; `game_send` is a bare write".
That was true and is not: `game_send` goes through the gate. The memory entry
is stale.

**Player config.** Lane Q is complete: macros, aliases, highlights,
substitutes, gags, variables and presets are edited in this client, in forms,
with a read-only Genie importer and no write path back into a Genie install.
`DOMAIN.md:597` ranks the config problem as *the* unambiguously worth-solving
one — for the client's own settings, it is solved.

**Sign-in and reconnect.** Native `eaccess.play.net` login
(`src-tauri/src/eaccess.rs`, `sal.rs`), password only in Windows Credential
Manager and only if asked, capped reconnect with a real backoff. Untested with
a real account — N7 is `[!]` and blocked on Dan, and that has not changed.

**The world content pipeline and the scene editor.** 86 zone files under
`src/data/world`, 17,750 rooms classified, a scene editor with a bounded
override store and an import schema that refuses a bad file with the reason on
screen (Lane S). It edits content, not geometry, so the 2D turn did not
invalidate it.

**Sound.** Ambient by zone across 85 zones, alerts, a 178-track music library,
a master control. Six green suites. `PLAY-BRIEF.md:69-75` sets the policy —
sound for what you need when you are *not* looking — and the ratio is
deliberate.

**Reading the game text.** `src/lib/gameStream.ts` (767 lines) is a careful,
adversarially-documented XML parser: vitals from the tag's `text` and never
its `value`, three-state indicators plus absence, provenance on every value
(`Sourced<T>`), and an explicit list of what DragonRealms will never send so
no panel waits forever for it. `StreamTabs` labels channels from the game's
own stream ids rather than inferring them.

**The script library and the Python task API.** 234 installed scripts, all
catalogued into 12 categories with three tiers; `list_scripts` and
`start_script` both implemented; a script editor; and a 3,184-line Python
automation API with its own tests. A player can already run `combat-trainer`,
`go2`, `healer` and the rest from this client.

**The AI review runtime.** Journal, evidence store, claim store, job
producers, alert broker, scheduler, model and local providers, worker and host
— ≈1,100 checks, and it degrades honestly with no model present.

## 4. The rule this survey suggests, and it is not "build everything"

`DOMAIN.md:1154-1165` puts two futures side by side and prefers the second:
Companion owning every game behaviour, versus Companion being a GUI over
`dr-scripts`, driving a mature maintained suite rather than duplicating it.
The measurements support the second strongly:

- `C:\Ruby4Lich5\Lich5\scripts\data` holds **30 YAML files, 47,721 lines** of
  exactly the domains this client lacks: `base-recipes.yaml` 10,305,
  `base-stealing.yaml` 8,625, `base-sigils.yaml` 8,485, `base-spells.yaml`
  3,939, `base-hunting.yaml` 3,730, `base-crafting.yaml` 2,532,
  `base-town.yaml` 1,640.
- `data/elanthipedia/` holds 77,067 indexed page names, 6,987 weapons, 773
  creatures, 486 armours, 1,321 materials — and **nothing** on rooms, skills,
  spells, shops, bounties, quests or recipes.
- The client already ships the read half of the YAML story
  (`Companion::Yaml`), with the line-and-column error report that is the exact
  fact people currently paste into online parsers to find.

So the lanes written from this table are weighted accordingly: **read and
present the game's own answers, and write the community's own settings
files**, rather than reimplementing crafting, pathfinding or a bounty engine.
Where an activity intent is added (Lane R), the bridge starts a dr-scripts
script and reports its progress, the way `map_walk` already starts `;go2`
rather than reimplementing movement.

## 5. What this survey did not check

Named rather than folded into a silence, because a run that skipped something
must not be able to say it passed.

- **No live character.** Every row above is measured against the repository
  and the vendored bridge. Nothing here was observed in a DragonRealms
  session, and the four items in `LIVE-STATE.md`'s "known broken" list —
  no map database, empty channel tabs, unread console problems, skills
  reading zero — are quoted, not re-measured.
- **Behaviour of the 259 buttons.** `WIRING-AUDIT.md:73` says reachability was
  checked and behaviour was not. Still true; this survey did not change it.
- **`docs/INTERFACE-KNOWLEDGE.md` does not exist.** It was named in the brief
  that commissioned this page. `ls docs/INTERFACE-KNOWLEDGE.md` → no such
  file, control `ls docs/KNOWLEDGE.md` → present. Recorded so the next reader
  does not go looking.
- **Guild-specific systems** (Cleric rituals, Moon Mage astrolabe, Thief Khri,
  Necromancer sigils, Bard PLAY) were surveyed only as a group. `DOMAIN.md:317`
  lists them as things the client has no concept of; none has a row here
  because each needs its own study, and `LIVE-STATE.md:281-283` records that the
  Bard song catalogue is deliberately not being invented.
- **Whether any of the nine unimplemented intents is a bad idea.** `burgle` in
  particular is `NEXT-50.md:495`'s "sole acknowledged unspecced intent" and is
  a product decision, not an engineering one. Lane R defers it.
