## 2. What PR #517 actually did, and what it broke

#517 is +205 / −8,316 over 79 files. It deletes the 3D direction documents,
the 3D Godot scripts and scene, the appearance system, the primitive-world and
geometric-kit tooling, and the shared asset registry. That is right and it is
Dan's decision.

It was gated at its branch point. The consequences of the deletion reached the
build after that, and **the branch as pushed did not pass the gate.** Measured
here before any repair — `DRC_TEST_PORT=8101 npm run gate`, 609 s:

```
gate NOT PASSED: 12 of 12 stages ran in 609s
  failed:  suites, clippy, rust-tests, rust-release-knobs, godot
```

Six distinct failures, every one a direct consequence of the deletion, and
none of them visible from the plan or from the diff:

1. **The whole Rust build did not compile.** `src-tauri/src/viewer.rs:442` had
   `include_str!("../../godot/scripts/world_root.gd")` — a *compile-time* read
   of a file #517 deleted. It sits inside the test that cross-checks that Rust
   launches the viewer with the same `--live-presentation` flag the GDScript
   reads. `clippy`, `rust-tests` and `rust-release-knobs` all fell out of this
   one line, and so did `test:link-reconnect-break`, which reported
   `src-tauri/src/game_link.rs: its tests ran (0, floor 15)` — a floor doing
   exactly its job.
2. **`test:godot-fixture-contract`**, 1 of 69 red: the mock fixture's generator
   shells out to the deleted `tools/build-primitive-world-manifest.mjs`.
3. **`test:board-geometry-drift`** red: `0 mention block_top_y(, floor 2`.
   Every Godot placement script it measured is deleted. L8's own `pitfalls:`
   line predicted this exact number four days earlier.
4. **`test:world-content`** threw `ENOENT ... godot\scripts\shared_asset_content.gd`
   — the check that every primitive the content asks for has a factory
   registered in Godot, against a content pack that is gone.
5. **`test:node-projection` NOT RUN**, "a node module is missing" — the same
   deleted builder.
6. **The Godot stage failed**, 7 of 8 scripts: `live_status_states_test.gd`
   loads `res://scripts/world_root.gd` and got a null instance.

The lesson is one line in `docs/MERGING.md` — gate *after* the rebase, not
before — and it is filed as **V6**. A deletion is the change most likely to
break something that does not appear in its own diff.

All six are repaired on this branch. After the repair, same command, 665 s:

```
PASS  types · lint · suites · rust-fmt · clippy · rust-tests · break-first-screen
PASS  break-doc-claims · rust-release-knobs · break-ai-script-repair · godot · break-bridge-client

gate: 12 of 12 stages ran in 665s, no failures — but 7 thing(s) went unchecked
      in test:godot-fixture-contract, test:world-content, test:scene-registry,
      test:scene-editor.

```

**Twelve of twelve stages pass. Read the second line rather than the first.**
The gate's third outcome is not "green" and is not a failure; it is the state
`docs/MERGING.md` describes as "a suite declined a rule". Those seven are all
one fact — **there is no Godot content pack**, because the 2D one is not
written — and each is printed with its reason rather than swallowed. They were
crashes before this branch, which is worse: a suite that throws and a suite
that honestly declines look nothing alike to a reader and identical to a
counter. The four are closed by **T2** (a 2D fixture generator) and **T4** (the
sprite vocabulary), and each re-arms by itself the moment a `.gd` file
registering content factories appears — the detection is a scan for the
registration call, not a hardcoded filename. That was proved by building a
temporary pack and watching all four go from NOT CHECKED to checked, and a
deliberately wrong pack turn them red.

Suite totals across the repair: **164 passed, 0 failed, 0 not run, 4 partial,
6,979 checks** (from 159 / 4 failed / 3 not run / 6,897 across 166). Rust:
**269 tests, 269 passed**, from a crate that would not compile. Godot: **7 of 7
scripts, 100 checks**.

Two suites were retired rather than repaired, because their subject is gone

## 5. The plan decision: `[-]` superseded

The audit was red with 22 findings and the plan carried a header saying so on
purpose. That was honest for one working day, and it is the wrong steady state:
a plan whose own check is expected to fail is a plan on which nobody runs the
check, and it trains the next reader to skim past the one real finding.

Three repairs were possible and two were lies. Leaving the rows `[x]` keeps the
audit red forever. Deleting them destroys the history and the 6,225 recorded
minutes. **Editing their `touches:` to name surviving files makes the record
lie about what the increment did** — and #517 did exactly that to seven rows
(J2c, K1, K4, L1, L3, L4, L8), repointing them at `docs/NO-3D.md`, a file
created on 9 Sep, for increments that ran on the 5th and 6th. The audit passed
those rows because the path resolves, not because the claim held. All seven are
corrected here to `gone:` the file they actually touched.

The fourth repair is a marker. `[-]` **superseded** says: *this increment will
not be delivered in this form, and every file it would have owned is absent.*
`tools/plan-audit.mjs` enforces it:

- a `superseded:` line is required and must carry a date; one on a row that is
  not `[-]` fails too;
- `new:` and `gone:` paths must be **absent**, and plain paths must still
  exist — so a superseded row goes on checking its survivors instead of quietly
  becoming an unchecked row;
- nothing that is not itself settled may `depends-on:` a `[-]` increment;
- **a gate line may not name one.** A gate member that can never become `[x]`
  is a permanent red mark rather than a condition, and this is what forced
  Gate 3 to be rewritten in the same edit rather than left at 10/11 forever.

Eleven new self-test cases cover it, both directions, including the positive
controls — `[-]` is the marker that *suppresses* findings a `[x]` row would
raise, so a bug in it looks exactly like a clean plan — plus an assertion that
a superseded row's paths were actually examined, because a `[-]` row that
quietly stopped checking anything would satisfy every other assertion by
producing no findings at all. `node tools/plan-audit.mjs --self-test` passes 41
cases. `[-]` previously meant "dropped" and had never been used once, so
nothing was rewritten to make room.

Sabotaged against the real plan, not only the synthetic one, each restored:
removing K2's `superseded:` line → `FAIL K2 is [-] superseded but has no
superseded: line`; putting L6 back into Gate 3 → `FAIL gate "3 Viewer optional"
names L6, which is superseded`. Positive control on the same runs:
`plan ok: 169 increments, 745 paths checked, 6 awaiting, 8 gates with 118
members`.

## 6. The new lanes

**Sequencing first, because it decides what to pick up next.** Dan, 9 Sep
2026: *"outside of godot we need to get the build running and tested as a mud
client without godot, all on its own… godot is dessert."* **Gate 1 comes
first.** Lanes T and U are written now so the interface is settled and the
Godot owner is not blocked on a conversation, but a session with free hands
should take Gate 1's remainder or Lane V before starting either. The same
instruction settles a second question — *"any ancient history won't need to be
merged into the windows, godot supersedes all that"* — so the map window and
the retired panels are **not** to be ported into Godot. Lane U publishes data;
what Godot draws with it is a fresh design, not a migration.

**Lane T — Godot 2D isometric presentation, the backend half.** Six
increments. The backend owns the manifest shape, the wire protocol, the intent
vocabulary and their tests; the Godot owner owns every scene, script and
sprite. T0 comes first and is a measurement, not a change: the Rust bridge
deserialises the snapshot into its own structs and re-serialises it, and
`WorldCell` there declares only `id`/`title`/`position`/`exits` while `Exit`
declares only four fields — so `board`, `content`, `tetherKind` and
`boardAnchor` are very likely **dropped in transit today**, silently. The
`player` field's own doc comment records this exact hazard as the reason
`player` had to be declared, which is the tell. Deciding which fields die
before establishing which ones ever arrived would be deciding about nothing.
T1 is then the field-by-field decision (metres out, normalised offsets and a
draw order in, `boardAnchor` migrated rather than deleted because
`aiJobProducers.ts` still reads it). T3 closes the unguarded seam: nothing
compares Rust's `PROTOCOL` and four intent variants against the TypeScript
side, and the two existing drift tests are about the *Lich* bridge, not this
one — which is why it reads as covered.

**Lane U — Godot as the MUD front end.** Five increments publishing each
panel's data over the existing bridge as a tested contract. Three rules: the
React panel stays until Godot renders it and Dan says which goes; no second
catalog (extend `panelDataContracts.ts`, which already declares per panel what
it reads and whether it needs a live character, enforced by a test that
re-derives the panel list from the real source); one publisher. U3 is the one
that matters most — the command lane's `canSend` **and its `reason`**, because
a viewer that knows it may not send but not why will invent an explanation, on
a client that drives a live character.

**Lane V — backend continuation.** N7 (Dan's), #505 (another session's live
worktree — read V2 before touching it), #509, the `lich.rs` sweep, the
re-gate-on-merge rule, Godot's mixed 2D/3D project settings (the Godot owner's,
recorded so the mixed state is not mistaken for a decision), and **V7**, the
memory-hygiene check: `docs/`, `AGENTS.md`, `.claude/` and the plan must carry
no surviving 3D instruction, verified by a grep that prints N of N so a scan
that matched nothing because it was pointed at the wrong tree reports itself
instead of certifying a clean repo.
